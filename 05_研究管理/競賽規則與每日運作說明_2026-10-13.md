## 要一直盯盤嗎？

已讀規則沒有要求人或 Agent 全天候盯盤。正式流程為開盤前提交當日決策，再由主辦方收盤後結算。

需要確認的是每日流程能完成：資料更新、取得最新帳戶狀態、Agent 執行、格式及交易限制檢查、成功提交、結算與違規狀態確認。定時執行加上失敗告警是可考慮的方案，不代表已决定部署，也不代表必須全天候呼叫模型。

人可以監看流程是否故障；投資決策及官方交件內容须依規則由 Agent 產製，不能由人直接改成想買的股票／數量。開賽後修程式、改提示詞或策略的允許範圍，以及人工純上傳未修改的檔案是否允許，仍應向主辦方確認。

## Agent 的決策範圍

使用者的描述「買哪些股票→什麼時候買→各買多少→什麼時候調整或賣出→判斷錯了怎麼處理」大致成立，但應解讀為：

1. 哪個交易日建立、加碼、減碼、出清或續抱哪些股票。
2. 各股票目標權重與整體現金比例。
3. 使用哪些已公布資料，為什麼形成這項決策。
4. 哪些反方證據／風險訊號使原判斷需要修正，在後續每日決策中如何回應。

「什麼時候買」不是指定盤中 10:05 或任意限價成交。此賽事按開盤前方案、當日均價結算，不能當沖；盤中觸價即刻停損不是已確認可使用的功能。價格上漲使持股超限也需監測，辦法另有調整寬限規定。

## 每日交件：D-Plan JSON

每個交易日交一份決策檔，不是事後填當天獲利的 Excel。即使不交易，昨日持股也要有續抱理由，不可因此不交件。

| 欄位 | 白話內容 |
|---|---|
| schema_version、doc_type、team_id、trade_date | 版本 4.3、文件類型、官方隊伍代號與目標交易日 |
| sources | 用過的資料來源、網址、資料描述時點 |
| observations | 從來源取得的可核對事實及數字 |
| market_view | 大盤判斷、操作姿態、淨買賣意圖與預計現金區間 |
| inferences | 根據事實、策略邏輯形成個股推論，交代反方證據 |
| decisions | 新建 BUY、加碼 ADD、減碼 TRIM、出清 SELL_ALL，目標權重及推論引用 |
| no_trade_decisions | 每檔不調整的持股及理由引用 |
| orders | 股票代號、BUY／SELL、委託股數與決策引用 |
| agent_metadata | 模型、執行起訖時間、程式版本；Token 用量等選填資訊 |

每筆委託要能追溯至決策→推論→事實→來源。每一檔昨日持股需出現在異動或續抱清單之一。

股數按官方公式機械換算，不能人工隨意改：

```
目標股數 = floor(目標權重 × 前日淨值 ÷ 前日收盤價 ÷ 1000) × 1000
委託股數 = 目標股數 − 目前持股數
```

股數為 1,000 股的倍數。前日帳戶與持股以 DataPack 系統結算資料為準；沒有結算資料時應重試下載，不能把 null 當成沒有股票。

## 均價與收盤價：用途不同

| 用途 | 價格／資料口徑 |
|---|---|
| 開盤前將目標權重換成委託股數 | 前一交易日收盤價與前日淨值 |
| 主辦方計算當日買賣成交 | 當日成交均價；舊版官方指南解釋為成交金額÷成交股數 |
| DataPack 內持股估值與可交易淨值 | as_of_date 的收盤價；nav_tradable = cash + 股票股數×收盤價加總 |

例如昨日收盤 100 元、今日成交均價 102 元、今日收盤 105 元：委託數量用昨日 100 元估算；實際買入成本按 102 元另加費用；日末持股估值按 105 元。這是價格用途示例，不是完整投資組合或官方行情。

當日均價在交件時還未形成，不能在早上先知道成交成本，應為現金與權重留緩衝。總資產 aum 可能包含未到帳的配息配股，不能用來替代 nav_tradable 算可交易權重。

## 每日時間流程

- 首次窗口：10/26 19:30～10/27 08:55，目標交易日為 10/27。
- 後續交易日：前一日 19:30～當日 08:55 收件，以主辦方系統時間為準；每日最多提交 25 次，不代表有 25 個盤中交易時點。
- 收件前：到文件繳交頁取得 DataPack，檢查 trade_date、as_of_date、missing、現金、持股與違規；再產出並檢查 D-Plan。
- 提交後：確認系統成功收件／檢核狀態，保留檔案及版本。沒有證據不能宣稱平台有公開上傳 API。
- 19:00：查看更新的淨值與結果；下一輪核對 DataPack 的 prev_day_orders，確認 executed、voided、excluded_codes 等狀態。

## 主要限制與資格風險

- 10 億元虛擬本金，股票範圍為官方 150 檔名單。
- 每日持股 20～30 檔；台積電權重上限 25%，其他各股上限 10%。
- 現金不能為負；PDF 寫不超過 25%，網頁及指南有「小於 25%」說法，實作宜留在 25% 以下並保留緩衝，邊界需確認。
- 不得融資、融券、借券、放空、當沖或零股交易；指南委託數量為千股倍數。
- 買賣手續費各 0.1425%；賣出另扣 0.3% 證交稅。
- 10/5 更新的 Active Share 規則為前 15 大持股、15% 門檻；連續兩交易日低於門檻可能取消資格。網頁正文仍顯示舊前 10 大／20%，應以更新公告／辦法核對，不照抄舊正文。
- 漏交、負現金、現金或持股限制不符等依辦法記警告，累積三次取消資格；不是每次技術提示都等於警告。DataPack 分 violations（違規天數）與 notices（不計入取消資格的提示）。
- 如超限源於股價波動而非加碼，辦法有五交易日調整期、第六日仍超限記警告的條款；不能概括成每次价格漂移立即取消資格。
- 舊辦法一般描述委託全成交，新指南／DataPack 明確有整批作廢或特定股票不成交情況，必須讀系統結果，不自行假設成交。

## 尚需確認的操作細節

### 截止前重交與 T+2 資金疑問

- D-Plan 不是一上傳就絕對不可更改：官方指南允許同日重繳、使用同一檔名，官網每日提交上限 25 次。需在收件窗口內重交 Agent 產出的版本；系統究竟採最後成功件或其他版本選取方式仍待确认，不能直接推定。
- 截止後不能用當日盤中／收盤結果回頭更改已提交的交易；收盤後分析結果，供下一交易日決策使用。
- 2026-10-13 重新讀取官方 DataPack 規格 §2.4：cash 為可動用現金，但「不等於當日買進上限」，交割以淨額計，同日賣出款也計入結算。因此此模擬競賽計算當日資金時可計入同日賣股所得，不需另等 T+2 才能支應當日買單。
- 示意：原現金 100 萬、同日賣出所得 200 萬、買進支出 250 萬，若都成交，扣交易費用前日末現金為 50 萬；費用及實際當日均價仍需計入，且需符合其餘限制。
- 應收配息 receivable_cash 不同：規格明文賽期內不會到帳，不可用於下單。虛擬現金不是可提領的真實銀行款項。

1. 官方自動下載／上傳 API 與登入方式；人工僅協助上傳的允許範圍。
2. 初次建倉應採哪個前日淨值及價格基準，以實際 DataPack／主辦方說明確認。
3. 決策程式／提示詞開賽後更新限制。
4. 現金 25% 邊界，以及 Active Share 的精確權重與基準日期口徑。
